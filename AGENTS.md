# AGENTS.md — ПДД Грузии

Контекст для агентов (Cursor и др.) и людей, продолжающих работу. Подробная техническая документация — `README.md`;
здесь — суть, принятые решения, жёсткие правила и текущее состояние. Как писать и править урок, одинаковый промпт очереди одного выпуска и промпт ролика — `docs/lesson-prose.md`. Состояние очереди уроков — `docs/agent/PDD_LESSON_STATE.md`, дыра разборов — `node tools/lesson-gap.mjs`. Состояние роликов — `docs/agent/PDD_VIDEO_STATE.md`, следующий ролик — `node tools/video-gap.mjs`. Исходный диалог, из которого всё выросло, — `history/`.

## 1. Что это
Курс по правилам дорожного движения **Грузии** (закон «О дорожном движении», редакция 25.06.2026, Matsne) на русском.
- Сайт: https://jenya239.github.io/pdd-georgia/ (GitHub Pages). Собранный сайт — `site/`. `docs/` — документация по разработке. Репозиторий `jenya239/pdd-georgia`. Пуш в `main` публикует `site/` через `.github/workflows/pages.yml`. Сайт в `docs/` не переносить.
- Выпуски: **ep01–ep03 — видео** (Аня учится водить, Макс спорит, инструктор Сергей Павлович); **с ep04 — текстовые уроки
  с иллюстрациями** (SVG/PNG-схемы) — дешевле и не хуже. Ролики в будущем — только по особо трудным темам.
- Метод подачи: ситуация, из которой видно, какое действие выбрать, затем норма, которая это действие держит, затем случай, где решение меняется. Определение входит в речь, когда без него эту ситуацию не решить. Онтология задаёт состав норм и не задаёт порядок абзацев. Где курс договаривает за молчащий пункт, это одно предложение рядом, без плашки после каждого раздела. Порции небольшие.
- Тон взрослый, без детского заискивания. **Жаргон и термины расшифровываются при первом упоминании.**
- С **ep07** текстовый урок не ведётся диалогом Ани, Макса и Сергея Павловича. Образец прозы — связный рассказ в `packages/lesson/ep07.ts`, не комментарий к определениям. Кривой перевод — приписка под цитатой; если цитата переворачивает правило, приписка заметная и говорит верное чтение (`docs/lesson-prose.md`). Видео ep01–ep03 с этими ролями не переписываются. У нового выпуска одна проза. Кнопки «Коротко» нет.
- У **ep04–ep06** две редакции одного урока. «С диалогом» — прежний текст. «Без персонажей» (`content/lessons/epNN/plain.mjs`) — те же нормы связным рассказом о действии на дороге; у выпуска 4 это три главы. Старый текст не удаляется. Выбор на странице выпуска, по умолчанию диалог.
- У **ep01–ep03** ролик не переписывается. Рядом с ним текст «Без персонажей» (`content/lessons/epNN/plain.mjs`): те же нормы, без Ани, Макса и Сергея Павловича. По умолчанию на странице остаётся ролик.

## 2. Методика: накопительная проверка и типичные ошибки
- Каждый урок заканчивается **накопительной проверкой**: все билеты этого урока **и всех предыдущих**, каждый раз целиком,
  по нарастающей (`check.html?lesson=epNN`, история результатов, можно прервать и продолжить).
- Ошибки копятся по билетам; **типичные ошибки** (`errors.html`) разбираются отдельно: выбранный неверный ответ рядом
  с правильным, заблуждение, цитата нормы; билет уходит из разбора после двух верных ответов подряд.
- Пробный экзамен: 30 вопросов / 30 минут, допустимо 5 ошибок (формат — `data/sources/exam_format/`).

## 3. Онтология (`content/ontology/`, код — `tools/pdd/ontology.py`) — ядро курса
Онтология не приложение к тексту. Урок, билет, наша задача и будущий компаньон читают одни и те же нормы, понятия и назначение. Правило, которого нет в онтологии, в курс не попадает; проза урока не подменяет норму. Расчёт назначения и отчёта — `packages/domain/ontology.ts` (без файлов и DOM; загрузка источников — `tools/load-ontology.mjs`). Сборка пишет `content/ontology/generated/report.json` командой `node tools/ontology-report.mjs` и кладёт билет в урок по `node tools/ontology-report.mjs --assignment`. Текст урока — `packages/lesson`. Сайт собирает `node tools/build.mjs`. Python `tools/pdd/build.py` ещё собирает то же дерево, и тест сверяет их. Видео и e2e остаются на Python.
Сущности: **Норма** (Norm: статья/пункт/подпункт, знак, разметка; 1459 шт., генерируются из закона и приложений) ·
**Понятие** (Concept) · **Урок** (Lesson: какие нормы излагает `teaches`, какие понятия вводит/использует) ·
**Билет** (Ticket: аннотация — проверяемые нормы/понятия, неверные варианты → заблуждения) ·
**Заблуждение** (Misconception) · **Проверочный элемент** (CheckItem — наши задания, `content/checkitems/epNN.json`).
- Тесты целостности (`tests/py/test_ontology.py`): нет висящих ссылок, понятие вводится раньше использования, и т.д.
- **Урок билета не назначается руками** — его вычисляет `World.derive_assignment()`: самый ранний урок, покрывающий основную
  норму, при условии, что введены все понятия билета; иначе билет «заблокирован». Чинят онтологию, а не списки.
  `context_norms` — нормы, нужные для контекста, но не являющиеся основной.
- **Наши билеты/задания** генерируем там, где нужнее (дыры официальной базы, частые ошибки): явно помечены «наш вопрос»
  и **привязаны к норме**; сборка отклоняет задание, если цитата расходится с законом или оно опирается на непройденное понятие.
- Итог назначения, заблокированные билеты, пробелы — `content/ontology/generated/report.json` (пересобирается; `build.py --check`).

## 4. Ссылки на нормы

## 6. Единая панель «после ответа»
- **Один компонент** (`packages/domain/details.ts` + `web/assets/app/details.mjs`) везде, где встречается билет:
  тренировка, уроки, накопительная проверка, ошибки, разбор экзамена. **Во время идущего экзамена не показывается.**
- Порядок вкладок фиксирован: **Пояснение · Разбор · Нормы · Моя история · Типичная ошибка · Заметка** (пустые скрыты).
- Прогресс: журнал попыток, заметки. Файл прогресса — **схема 4** (`SCHEMA_VERSION` в
  `packages/domain/registry.ts`); экспорт/импорт и миграции 0–3 → 4 — `packages/domain/bundle.ts`.
  Слияние соединяет попытки по id и не складывает счётчики. Хвост схемы 3, который был только в счётчиках, остаётся одной сводкой и при повторном импорте заменяется. Меняя формат —
  поднять версию и добавить миграцию + тест. Новый раздел прогресса регистрируется в `registry.mjs` (тест не даст забыть).
  Сборка пишет хеш текста каждого билета (`packages/domain/ticket-hash.ts`); серия верных смотрит на него.

## 9. Инженерные правила (жёсткие)
- **Весь код — в этом репозитории.** Clean code, clean architecture, **TDD** (сначала тест).
- **Новый код — Node.js 24** (Active LTS, с 24.22; `.nvmrc`, `package.json`). Python не расширять. Ruby — только если у Node нет годной библиотеки; так же устроен внешний разбор через `mlc-support`. Видеопайплайн ep01–ep03 на Python не переписывать ради смены языка.
- Чистый домен — `packages/domain/*.ts` (без DOM/хранилища; `node --test tests/js`, проверка типов `tsc -p packages/domain`). Сборка выпускает его в `site/assets/domain/*.mjs` (`tools/emit-domain.mjs`): браузер TypeScript не исполняет. DOM — `web/assets/app`, страницы —
  `web/assets/pages`. Python: сборка и парсеры — `tools/pdd` (pytest, `tests/py`). Видео — `video/` (`tests/video`, пиксель-в-пиксель).
  E2E — `tests/e2e/site_e2e.py` (headless Chrome/Chromium через Playwright, сайт под `/pdd-georgia/` как на Pages).
- **`tools/check.sh` должен печатать `ALL GREEN` перед каждым коммитом/пушем.** `site/` — артефакт сборки, коммитится
  вместе с исходниками (`build.py --check` падает, если устарел). `docs/` — документация, не сайт.
- Секретов в репозитории нет и не будет: `tests/py/test_secretscan.py` сканирует все отслеживаемые файлы и `history/`.
