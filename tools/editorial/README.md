# PDD Georgia — редакционный конвейер для GrokBot

**Продолжение работы после пилота ep04:** основной вход — [LITERARY.md](LITERARY.md). Выполни сначала литературную редактуру текущего ep04, затем ep02 и остальные выпуски, с независимым сравнением и проверками. START.md — базовый процесс, FOLLOWUP.md — требования предыдущего прохода.

**Запуск:** передай GrokBot каталог целиком (распакуй ZIP рядом с рабочей копией PDD Georgia или в `tools/editorial/`). Попроси: «Выполни START.md полностью. Начни с независимой проверки ep04, затем последовательно пройди весь объём». Не нужно копировать прежние большие задания.

- `START.md` — единое задание управляющему агенту, порядок работы и приёмка.
- `roles/` — короткие независимые контракты автора, аудитора, редактора и производителя комплекта.
- `input/ep04-candidate.md` — полная новая рукопись ChatGPT без прежней инструкции. Это кандидат, не опубликованный урок.
- `runner.mjs` — простой журнал запросов/ответов, Node ESM, без зависимостей. Не вызывает Grok API, не оценивает ответы и не запускает этапы сам. GrokBot ведёт последовательность по START.md, используя реальные независимые вызовы, которые доступны в его окружении.

## Минимальный рабочий ход

Сначала управляющий агент собирает проверенный `spec.json` из закона и онтологии. Готовит отдельный входной Markdown для аудитора: спецификация, точные источники, полный текст кандидата, SHA-256 текста, границы проверки. Для пилота добавляет полный `input/ep04-candidate.md`, не заменяет его опубликованным текстом. Для остальных ролей вход собирается по контракту роли. Не включать в авторский вход закрытые ответы или результаты независимого финального holdout.

Из рабочего каталога репозитория (подставь фактический путь к пакету):

```sh
node tools/editorial/runner.mjs prepare ep04 review ep04-review-input.md
# Выведет каталог editorial-runs/ep04/jobs/review-<hash>.
# Передай prompt.md из этого каталога отдельному аудитору GrokBot.
# Сохрани реальный ответ отдельно в ep04-review-response.md.
node tools/editorial/runner.mjs record editorial-runs/ep04/jobs/review-<hash> ep04-review-response.md metadata.json
node tools/editorial/runner.mjs list ep04
```

`<hash>` заменяется фактическим именем каталога, выведенным prepare. Не вводи его буквально. Для каждой следующей роли меняй вход (например, `edit`, `write`, `materials`) и сохраняй новую версию результата. Повторный prepare с тем же входом и ролью вернёт ту же работу; record не перезаписывает предыдущий ответ. Для намеренного повторного независимого вызова добавь во вход идентификатор попытки. Хеши защищают от случайной подмены, не доказывают истинность ответа. `recorded` означает только сохранённый ответ, не успешную проверку.

Пример `metadata.json` (укажи фактические значения):

```json
{"model":null,"execution":"manual-independent","costUsd":null,"notes":"Отдельная сессия GrokBot; стоимость не измеряется"}
```

Не маркируй mock как live. Если нет отдельной сессии, `unknown` и блокер независимой проверки. Запросы/ответы не должны содержать секреты. По умолчанию журнал сохраняется под `editorial-runs/`, можно задать иной каталог четвёртым аргументом prepare и вторым аргументом list. Выбранные артефакты и решения сохраняются в рабочей ветке; не коммить секреты и временные файлы.

## Доказательства по выпуску

Достаточно следующей структуры (можно использовать существующие каталоги проекта вместо новых):

```text
editorial-runs/ep04/
  spec.json              # источники, атомарные требования, ограничения
  candidates/            # исходник, PR, редакторские версии
  holdout.json           # задачи и ответы отдельно от оптимизации
  jobs/                  # неизменяемые prompt/response, receipt
  decision.json          # выбранный хеш, проверки, нерешённые дефекты
  integration.md         # изменённые файлы, тесты, сборка и статус медиа
```

Нужна настоящая редакторская работа и независимая проверка, а не заполнение этой структуры для галочки. Основной маршрут — обычный смысловой аудит, без обязательного ReaderSim. Никаких новых архитектурных слоёв, пока не наблюдается конкретная проблема.
