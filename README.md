# ПДД Грузии: учебный сайт, данные и видео

Сайт: https://jenya239.github.io/pdd-georgia/ (GitHub Pages). Один репозиторий: сайт, сборка данных, скрапер и парсер билетов, парсер закона, онтология, генераторы уроков, видеоконвейер, тесты.

**Агентам и новым участникам — сначала [`AGENTS.md`](AGENTS.md)** (суть проекта, принятые решения, правила, статус и следующие шаги). Архив исходного диалога — [`history/`](history/).

## Архитектура

```
content/            ИСХОДНИКИ, которые пишет человек
  checkitems/         наши проверочные вопросы к урокам (epNN.json, пишутся вручную — это исходник, генератора нет)
  episodes.json       выпуски: план (E-номера), ключевые пункты, цитаты, teaches, pitfalls
  lessons/epNN/       генераторы текстовых уроков (lesson.py → HTML; figs.py — SVG-схемы)
  media/              опубликованные видео и постеры выпусков (epNN.mp4/.jpg)
  assets/signs/       картинки знаков (общие для уроков и видео)
  plan/               план курса (structure.md: блоки и E001–E107)
data/               ВНЕШНИЕ ДАННЫЕ, полученные скриптами
  sources/            тексты закона (RU/KA — matsne, ред. 36 от 25.06.2026; EN — офиц. перевод 2019), приложения, КоАП (KA)
  tickets/            база билетов teoria.on.ge (tickets_ru.json, картинки), manual_fixes.json
packages/domain/    доменная логика на чистых ES-модулях (без DOM): прогресс, хранилище, области проверки, ошибки
web/                страницы сайта: *.html (без инлайн-скриптов) + assets/
  assets/app/         общий слой страниц: dom, prefs (тема), data (загрузка JSON), progress, layout, question
  assets/pages/       по одному модулю на страницу (index, episode, check, errors, practice, exam, about)
tools/              сборка и конвейеры данных (Python)
  build.py            точка входа сборки → docs/
  pdd/                чистые функции: assign (билет→урок), episodes, lawparse, plan, lessonkit; build = ввод-вывод
  pdd/tickets/        scrape → parse → fetch_images → build_tickets
  check.sh            все проверки разом
video/              видеоконвейер
  render.py           единая точка входа: python video/render.py epNN [tts|video|all|still T…|sheet]
  engine/             общий движок: core (кадры PIL → ffmpeg), lib (рисование), cast (персонажи, голоса), tts, assemble, subs, music, final.sh
  episodes/epNN/      только своё: scenes.py (сценарий), boards.py (доски), timeline.json
tests/              js (node --test), py (pytest), video (кадры против эталонов), e2e (Playwright)
docs/               СОБРАННЫЙ САЙТ (артефакт сборки, коммитится, его публикует Pages)
ci/test.yml         шаблон workflow GitHub Actions (см. «CI»)
```

Зависимости направлены в одну сторону: `content` + `data` → `tools` → `docs`; страницы (`web/assets/pages`) → `web/assets/app` → `packages/domain`. Доменные модули не знают про DOM и `localStorage`: хранилище подключается адаптером `createStore(backend)` (в браузере `localStorage`, в тестах `memoryBackend()`).

Сборка читает только файлы внутри репозитория (это проверяет `tests/py/test_build.py`).

## Сборка

```
python3 tools/build.py           # пересобрать docs/
python3 tools/build.py --check   # только проверить, что docs/ актуален (ничего не пишет)
python3 tools/build.py --out=DIR # собрать в другую папку
```
Сборка генерирует `docs/data/tickets.json`, `docs/data/items.json` (наши вопросы и заблуждения), `docs/data/episodes.json`, HTML текстовых уроков, копирует страницы, `web/assets`, `packages/domain` (→ `docs/assets/domain/`), картинки билетов (→ `docs/img/`), видео и знаки, пишет `.nojekyll`.

Локальный просмотр: `nvm use && npm run dev` → http://127.0.0.1:8000/pdd-georgia/ (с `file://` не работает — данные грузятся через `fetch`). Нужен Node.js 24.22+, Active LTS.

## Публикация (GitHub Pages)

Публикуется папка `docs/` ветки `main`. Workflow для деплоя не нужен (у токена нет scope `workflow`).
Чтобы Pages брал сайт из `docs/`, один раз переключите источник:
```
gh api -X PUT repos/jenya239/pdd-georgia/pages -f "source[branch]=main" -f "source[path]=/docs"
```
(или Settings → Pages → Branch: main, folder: /docs). Пока Pages смотрит в корень ветки, корневые `index.html` и `404.html` перенаправляют в `docs/`, в том числе старые ссылки вида `…/pdd-georgia/episode.html?id=ep01`. После переключения корневые файлы просто не публикуются.

## Тесты

```
tools/check.sh                         # всё: node, pytest, build --check, e2e
node --test tests/js                   # доменные модули (Node 18+)
python3 -m pytest -q tests/py          # сборка, назначение билетов, уроки (цитаты дословно из закона), онтология, билеты
python3 -m pytest -q tests/video       # кадры видео пиксель-в-пиксель против tests/video/baseline (пропускается без видео-venv)
python3 tests/e2e/site_e2e.py [--root=docs] [--shots=DIR]   # Playwright, сайт как на Pages (под /pdd-georgia/)
```
Переменные `check.sh`: `PYTHON` (с pytest), `E2E_PYTHON` (с playwright), `VIDEO_PYTHON`, `E2E=0` — пропустить браузер, `E2E_CHANNEL=chromium` — встроенный Chromium вместо Chrome.
Зависимости: `pip install -r requirements-dev.txt`, затем `python -m playwright install chromium`.

### CI
`ci/test.yml` — готовый workflow (node + pytest + build --check + e2e). Он лежит не в `.github/workflows/`, потому что токен без scope `workflow` не может пушить workflow-файлы. Включить: `mkdir -p .github/workflows && cp ci/test.yml .github/workflows/` и запушить токеном со scope `workflow` (или создать файл через веб-интерфейс GitHub).

## Новый выпуск
Выпуск бывает двух видов (`kind` вычисляет сборка):
- **видео** — `content/media/epNN.mp4` и `epNN.jpg`; исходники видео — `video/episodes/epNN/`;
- **текст** — генератор `content/lessons/epNN/lesson.py` с функцией `render()` → фрагмент HTML (маркер `<!--AFTER-TICKETS-->` делит теорию и заключение; между ними сайт показывает билеты и «наши вопросы» из `content/checkitems/`. Своих вопросов прямо в тексте урока нет — `tests/py/test_lessons.py`). id внутри SVG обязаны начинаться с `epNN-` (проверяет `tests/py/test_lessons.py`, там же — что все цитаты дословно есть в законе).

Затем добавьте запись в `content/episodes.json` и запустите `python3 tools/build.py`.

### Видео
```
/workspace/.videovenv/bin/python video/render.py ep03 still 52.6   # кадр → video/episodes/ep03/stills/
/workspace/.videovenv/bin/python video/render.py ep03 all          # озвучка (edge-tts) + рендер → final.mp4
```
Результаты рендера (audio/, seg/, stills/, *.mp4) в git не попадают; готовое видео копируется в `content/media/`. Нужны numpy, pillow, matplotlib, edge-tts, ffmpeg и шрифты из `/usr/share/fonts/truetype/sand-box/google/`.

## Билет → урок (поле `lesson`)
У каждого билета не больше одного основного урока. Поле `lesson` вычисляет сборка из онтологии — `World.derive_assignment()` (`tools/pdd/ontology.py`; в `data/tickets/tickets_ru.json` оно не пишется). Ручных списков билетов нет:
1. **Основное правило** билета — первая ссылка на закон (статья, пункт, грузинский подпункт), а если её нет — первый пункт приложения (знак, разметка).
2. Кандидат — **самый ранний** выпуск, у которого `teaches` покрывает это правило. Спецификации: `"ст. 39"`, `"ст. 39 п. 1"`, `"ст. 34 п. 9 д"`, `"прил. 1 1.1"`.
3. Билет попадает в урок, только если к нему введены **все понятия билета** (см. «Онтология курса»). Иначе он «заблокирован» и остаётся без `lesson`.
4. Если билет не туда попал или выпал, правят онтологию (что урок излагает, понятия, аннотацию билета с `note` — почему), а не список билетов.

Поле `episodes` (тематические ссылки на билеты) остаётся как было. `pitfalls` — заметки «почему здесь ошибаются» по правилу. Они берутся только из текста урока и показываются только у билетов этого урока (поле `why`).

## Онтология курса (`content/ontology/`)
Лёгкая модель «что чему учит», чтобы проверять порядок уроков и назначение билетов. Сущности:
- **Норма** — `generated/norms.json`, генерируется из закона (`tools/pdd/norms.py`): статьи, пункты, подпункты, пункты приложений и примечания к разделам приложений (`A1:1.прим.а`, `A1:3.прим2.д`). У нормы есть тексты RU/KA (EN, если найден) и редакция закона. Пункты приложения, которых нет в русском переводе, помечены `ru_missing` (сейчас это знаки 3.1 и 3.2).
- **Понятие** (`concepts.json`) — нормы (`norms`), в которых закон его формулирует. `gap` — пометка, если у понятия нет определения в законе.
- **Урок** (`lessons.json`): `introduces`, `relies_on`, `assumes` (общие термины, которые используются, но не объясняются) и `states` (нормы, которые урок излагает своими словами сверх `teaches`/`quote_refs` из `episodes.json`).
- **Билет** (`tickets.json`): дополнительные `concepts`/`norms`; `context_norms` — нормы, которые банк цитирует, но для ответа они не нужны (например, знак, который лишь называет обстановку; сборка проверяет, что такая норма действительно процитирована и не основная); `note` — почему билет в уроке или вне его; `distractors` — неверный вариант (индекс с 0) → **типичное заблуждение** (`misconceptions.json`) или `null`, если заблуждение не сформулировано.
- Нормы билета берутся из ссылок банка (статьи, пункты приложений, примечания вида «შენიშვნის „ა“ ქვეპუნქტი»).

`schema.json` описывает формат файлов. `tests/py/test_ontology.py` проверяет, что ссылки не висят, понятие вводится не больше одного раза и раньше, чем на него опираются, нормы введённых понятий уроком действительно изложены, а у каждого живого билета урока размечены все неверные варианты.

`World.derive_assignment()` назначает билет самому раннему уроку, который покрывает его основную норму и к которому введены все понятия билета. Если основную норму учат несколько уроков (например, ст. 36, п. 4 «в» — ep03 и ep06, где добавлен трамвай), билет попадает в первый из них, где понятий хватает. Если не хватает ни в одном, билет «заблокирован» в первом покрывающем уроке (`blocked` с недостающими там понятиями). Это и есть назначение сайта: сборка берёт его из `node tools/ontology-report.mjs --assignment`. Для сверки сборка вызывает ту же команду без флага (расчёт в `packages/domain/ontology.mjs`) и пишет `generated/report.json`: итог по урокам, заблокированные билеты с недостающими понятиями и `note`, «строгое» назначение (все нормы билета изложены) и его отличия, пробелы и неразрешённые ссылки банка. `build.py --check` падает, если этот файл или `norms.json` устарели.

## Нормы: постоянные страницы и автоссылки

**Страницы.** У каждой нормы онтологии (статья, пункт, подпункт закона; знак, разметка, примечание приложений — 1459 шт.)
своя статическая страница `docs/norm/<id>.html` и общий указатель `docs/norm/index.html` (с поиском). Страница: цитата,
текст RU (дословно), KA, EN (перевод 2019 г., помечен), редакция и ссылка на Matsne, родитель/дети/соседи, картинка знака,
«где это в курсе» (уроки, понятия, наши вопросы, билеты). Генератор — `tools/pdd/normsite.py`.

**Схема id** (`tools/pdd/normids.py`): `st5` — статья 5; `st5-p13` — ст. 5, п. 13; `st37-p6-a-a` — подпункт «а.а»
(буквы транслитерируются: а→a, б→b, в→v, г→g, д→d, е→e, ж→zh, з→z, …); `st11_1` — статья 11¹, `st21-p15_2` — п. 15²;
`sign-5.26` — знак; `mark-1.14.1` — разметка; `sign-1-notes-b`, `mark-1-notes2` — примечания к разделам приложений.
Id не меняются при пересборке: `tests/py/fixtures/norm_slugs.tsv` — снимок, в который можно только добавлять
(тест падает, если у существующей нормы изменился id).

**Автоссылки.** При сборке `tools/pdd/normref.py` (чистая функция, таблица реальных строк в `tests/py/test_normref.py`)
находит ссылки на нормы в уроках ep04–ep06, данных выпусков (ep01–ep03 — видео, у них ссылки в пересказе, тезисах и цитатах),
грузинских пояснениях билетов, наших вопросах, типичных ошибках и на самих страницах норм. Ссылка ставится только при
однозначном разрешении (явная статья; «настоящей статьи» в тексте закона; пункт без статьи — только если тот же пункт
в этом контексте цитирован ровно с одной статьёй и ни у одной другой упомянутой статьи такого пункта нет). Неоднозначное
и ненайденное остаётся текстом; счёт по типам — `content/ontology/generated/links.json`.

**Всплывающая панель** (`web/assets/app/normpop.mjs`, расчёт положения — `packages/domain/normlinks.mjs`): наведение
(250 мс) открывает панель справа от колонки текста (слева / под строкой, если места нет), фокус с клавиатуры — тоже,
Esc закрывает; на тач-экранах и ≤640 px тап открывает нижнюю шторку, второй тап — переход. Тексты грузятся лениво
по статьям: `docs/norm/chunks/<статья>.json`.

## Прогресс, накопительная проверка, ошибки
Прогресс хранится только в браузере (`localStorage`). Все ключи перечислены в одном реестре `packages/domain/registry.mjs`; код пишет ключи только через `KEYS.<id>`, а `tests/js/registry.test.mjs` падает, если где-то в `web/` или `packages/` встретился незарегистрированный ключ или ключ написан строкой мимо реестра:
- `pddge.progress.v1` — по билету и по «нашему вопросу»: попытки, верные, ошибки, серия верных подряд (освоение, «Разобрать ошибки»), дата последней ошибки, выбранные неверные варианты;
- `pddge.runs.v1` — результаты накопительных проверок;
- `pddge.cumrun.v1` — незаконченные проверки;
- `pddge.settings.v1` — настройки проверки;
- `pddge.exams.v1` — история пробных экзаменов;
- `pddge.theme` — тема.
- Язык: глобального переключателя нет (убран в 0.7). Вопросы показываются по-русски; у каждого билета вне идущего экзамена есть кнопка «оригинал (KA)» — показывает грузинский текст вопроса и вариантов. Непереведённые билеты (эко-вождение) идут на грузинском с пометкой. EN остаётся только в данных и на страницах норм (редакция 2019). Ключ `pddge.lang` выведен из реестра (`RETIRED`): при открытии хранилища удаляется, в старых файлах прогресса игнорируется.

Кнопки «Сохранить прогресс» / «Загрузить прогресс» есть в шапке каждой страницы. Файл — один JSON `{format: "pddge-progress", schema: 3, app, exportedAt, data: {<id из реестра>: значение}}` (`SCHEMA_VERSION` в `packages/domain/registry.mjs`). Старые файлы (схема 2 без поштучной истории ответов и заметок, схема 1 и голый словарь прогресса) мигрируются, файлы новее схемы отклоняются с понятным сообщением, некорректные разделы отбрасываются. Перед загрузкой показывается сводка «Сейчас / В файле / После» и выбор: «Объединить» (ответы суммируются, истории объединяются, незавершённые проверки, настройки и тема остаются здешними) или «Заменить» (всё станет как в файле). Логика — `packages/domain/bundle.mjs`, DOM — `web/assets/app/progress-file.mjs`.

Страницы:
- `check.html?lesson=epNN` — накопительная проверка: все билеты этого урока и предыдущих. Сначала идут новые билеты, потом прежние вперемешку (порядок можно сменить). Проверку можно продолжить после перезагрузки, есть история результатов.
- `errors.html` — типичные ошибки (рейтинг, по урокам, темам, правилам) и «Разобрать ошибки»: билет считается исправленным после 2 верных ответов подряд.

## Наши вопросы («наш вопрос», `content/checkitems/`)
Собственные проверочные вопросы к урокам, которых нет в официальной базе. Файл `content/checkitems/epNN.json` — список вопросов урока epNN (урок берётся из имени файла). Типы: `ticket` (в формате билета), `diagram` (схема: перекрёсток, поперечный профиль дороги, подъезд к переходу/переезду; поле `fig`), `priority` (кто проезжает первым), `max-error` («найдите ошибку в рассуждении Макса»), `flashcard` (число из закона), `cloze` (вставьте слово в цитату `«…___…»`).
Поля: `id` (`o-epNN-NN`), `type`, `q`, `options`, `answer`, `norms`, `concepts`, `quote` (`norm` + дословный русский текст), `explain`, `distractors` (каждый неверный вариант → заблуждение из `misconceptions.json` или `null`), `fig`.
Сборка (`tools/pdd/checkitems.py`) отказывается собирать сайт, если: цитаты нет дословно в норме; нормы, понятия или заблуждения не существуют; норма не изложена этим или более ранним уроком; понятие ещё не введено к этому уроку; размечены не все неверные варианты; у `flashcard` число не встречается в цитате; `cloze` с ответом не совпадает с цитатой; у `diagram` нет схемы. Правила не придумываются: каждый ответ подтверждается цитатой, которую сайт показывает после ответа (с редакцией закона).
На сайте: раздел «Наши вопросы к уроку» на странице выпуска; в накопительной проверке — переключатель «Включать наши вопросы» (по умолчанию включён, вопросы помечены); в «Типичных ошибках» — отдельная тема «Наши вопросы» и пояснение заблуждения при неверном ответе (и у билетов банка с размеченными вариантами). Пробный экзамен и тренировка по темам используют только официальную базу. Схемы рисует `packages/domain/figure.mjs` (без id внутри SVG). Тексты вопросов только на русском.
