# Ep03 v2 — производственный план: от карты знаний до релизного MP4

**Это техническое ТЗ для Grokbot**, а не обещание, что фильм уже собран. Сценарий и изобразительная логика лежат в этой папке; старые `video/episodes/ep03/scenes.py`, `boards.py`, `timeline.json`, `content/media/ep03.mp4` не изменены. **Не публиковать**, пока новый ролик не выдержит приёмку.

## 1. Контракты и deliverables

**Канонический источник речи и порядка сцен:** `scenario.json`. `SCREENPLAY.md` и `VOICE.txt` — генерируемые копии, а не независимые тексты. Команда:

```bash
node tools/ep03-v2.mjs --summary
node tools/ep03-v2.mjs --check
# после осознанной правки scenario.json:
node tools/ep03-v2.mjs --write
```

**Структура ожидаемого результата в папке v2/ (создать по мере работы):**

```text
video/episodes/ep03/v2/

  SCREENPLAY.md          # генерирует tools/ep03-v2.mjs
  VOICE.txt              # генерирует tools/ep03-v2.mjs

Крупные и промежуточные бинарники не коммитить без осознанной причины, использовать игнорируемый рабочий каталог или Git LFS. Документация, исходники кадров, маленькие проверочные рендеры и отчёты приемки допускаются в PR.

## 0. Производственный принцип: **сначала рассказ**

Ни графический движок, ни API генерации видео, ни выбор модели диктора не должны диктовать структуру выпуска. **Сначала нужен литературно связный монолог**, в котором каждая новая сцена вырастает из вопроса, оставленного предыдущей. Главный договор — [NARRATIVE_BIBLE.md](NARRATIVE_BIBLE.md); обязательна самостоятельная художественная вычитка без заголовков и картинок.

**Нулевой результат:** `render/narrative-review.md` (критический редакционный отчёт) и аудиочитка или временный TTS только речи, без графики. Укажите начало и разрешение центрального вопроса, 11 мотивированных переходов, явные провалы ритма и реальные замены до/после. После исправлений обновить `scenario.json` и обе производные копии; старые зафиксированные `estimate_s` могут измениться.

**До этого** не покупать инструменты, не делать сложную массовую раскадровку, не объявлять набор кадров фильмом. При юридических сомнениях **сверяться с законом**, а не создавать убедительное, но неправильное повествование.

## 2. Фазы, порядок работы, условия переключения

### Фаза 0 — литературная архитектура и испытание на слух

1. Прочесть принятую прозу выпуска `ep03` и [NARRATIVE_BIBLE.md](NARRATIVE_BIBLE.md), не копируя ни её абзацы, ни техническую разметку.
2. Из всех `voice` собрать одну речь; **прочитать её без S00–S11**. Найти потерянные переходы, где мысль не продвигается, а начинается новый пункт учебника.
3. Исправить макро-структуру: ложная уверенность → скрытая предпосылка → ложное изменение → подлинный переворот → усложнение → человек и реальность → возврат к исходному вопросу.
4. Провести литературный редакторский спор: две правдоподобные версии слабых связок, указать выигрыш/потерю каждой; проверить у независимого читателя или рецензента, не выдавая оценку автора за чужую.
5. Зафиксировать `render/narrative-review.md`; обновить `scenario.json`, выполнить `node tools/ep03-v2.mjs --write && node tools/ep03-v2.mjs --check`.
6. Юридическая сверка идёт независимо и имеет право заставить переписать любую «удачную» фразу, но не подменяет саму литературную работу.

**Блокер:** если после удаления заголовков слышно двенадцать отдельных объяснений, **переходить к полному рендеру нельзя**, даже если все правовые ссылки корректны.

### Фаза A — реконструкция и юридический каркас

Прочитать `AGENTS.md`, `docs/lesson-prose.md`, `docs/ep03-visual-gold-standard.md`, `content/lessons/ep03/plain.mjs`, `content/ontology/lessons.json`, `content/ontology/tickets.json`, `docs/real-road-cases-sourcebook.md`. Нельзя делать утверждения о билетах или знаках, пока не проверены исходные записи.

Для каждого `Sxx` выписать:
- что наблюдает зритель, какой вопрос возникает;
- что **единственное** изменяется относительно пары;
- `norm/source`, условия применимости, исключения;
- ожидаемый проверенный вывод, включая «не определено»;
- что в кадре было бы ложным доказательством.

Глобальные запреты из `scenario.json.legalGuards` проверять автоматически и отдельной независимой рецензией.

### Фаза B — сравнение рендереров на одной и той же микросцене

Разрешён любой подходящий инструмент — PIL + ffmpeg (существующий `video/engine/core.py`), SVG + Chromium/Playwright, Motion Canvas, Remotion, Canvas/WebGL, Blender с ортографической камерой, Manim, After Effects через проектные файлы, собственный GL-рендерер. Разрешены инструменты и API Grokbot, если они доступны в его среде и разрешены владельцем: выбирать инструмент **после** двух быстрых тестов, а не переписывать всё под любимый пакет.

**Минимальная конкурсная проба 1:** один и тот же `A2→A3` в 1080p со слоями машин; показать заплатку и постепенное продолжение асфальта, pause и смену правового вывода.

**Минимальная конкурсная проба 2:** `C1→C2`; показать изменение **типа дороги**, а не просто изменение картинки. Использовать тот же набор координат автомобилей.

Рендерер принимается, если делает правильные ключевые кадры, воспроизводимые переходы, не фликерит, позволяет менять сцену без переработки остального и сохраняет чёткие знаки на полной и мобильной ширине. Если один подход оказался объективно лучше, выбрать его — отсутствие дополнительных библиотек не является самоцелью.

**Нельзя** подменять эту фазу двумя «концепт-артами», где уже не совпадают автомобили и геометрия. Сравнивать одинаковое содержание при одинаковой задаче.

### Фаза C — каноническая модель сцены

Определить структуры:
- `world`: карта дорог, топология, сквозное/прилегающее назначение, количество полос, расположение знаков;
- `vehicles`: стабильный ID, геометрические координаты, направление, предполагаемый манёвр; неизменяемые свойства между контрфактами;
- `surface`: материальные классы и видимость поверхности; **не** напрямую правовой приоритет;
- `signs`: тип, сторона и ориентирование, точное официальное обозначение;
- `decision`: проверенный правовой вывод (включая `unknown`), источник, scope, зависимости;
- `visual-emphasis`: видимые только после проверки акценты;
- `camera`: top-down orthographic matrix; один и тот же transform для пары миров A/C;
- `time`: real audio cue, scene transition, outcome reveal, hold.

Пожалуйста, не храните юридический статус в цвете асфальта и не выводите юридическое решение из collision detection. Видимость, геометрия и правовая обязанность — три отдельные модели. Не используйте свободную LLM-генерацию как окончательный `decision`.

### Фаза D — покадровая раскадровка и дизайн

Для каждого Sxx сделать 3–5 still (до изменения / момент изменения / после / highlight), контакт-лист и краткую подпись `what changed`. На общих мирах сравнить плашки: нельзя случайно изменить размер машины или ракурс. Публичные профессиональные/обучающие визуальные референсы можно исследовать, но **не копировать** чужие схемы, кадры или стиль до совпадения.

Графическая сцена и речь работают попеременно: картинка сначала вызывает вопрос, затем раскрывает условие, затем диктор формулирует вывод. **Не** озвучивать абзац одновременно с его текстовым дубликатом на экране. Никаких персонажей, чат-переписок, «добрых преподавателей», игрового счёта.

### Фаза E — TTS, музыка, субтитры, точный монтаж

1. Голос — один. Синтезировать по `scenario.scenes[].voice[]` с неизменными текстами и stable IDs; старый `video/engine/tts.py` кэширует речь по MD5, но ожидает старую форму `BEATS`. **Не** переписывать `scenes.py` до победы прототипа; можно создать отдельный v2-адаптер или собственную TTS-сборку.
2. Доступны edge-tts, публичные/платные API, локальный TTS, живой диктор. Перед платным API подтвердить доступный бюджет и разрешение на расходы, хранить model/version/voice/rate/params. Не передавать секреты или private keys в репозиторий.
3. Сборка `timeline.json` из реальной длительности аудиофрагментов, пауз и действий. Ориентиры `estimate_s` и `pause_s` не заменяют фактического аудиотайминга. Полезны sentence-level cue IDs и waveform markers.
4. Субтитры `SRT/ASS`: смысловые фразы длиной комфортного чтения; не подписывать всю речь как статичную простыню. Сигналы/знаки на экране не должны накладываться на субтитры.
5. Звук: никакой фоновой музыки с неизвестной лицензией; оригинальная/разрешённая музыка либо тишина. Тихий room tone; при документальном эпизоде не добавлять драматического удара. Предусмотреть `--no-music` вариант.
6. Финальная сборка: H.264 / AAC, `yuv420p`, 1920×1080, 24fps или проверенный компромисс, `+faststart`, web-ready. Сохранять отдельные дорожки/субтитры, если это реализуемо без хрупкости.

Практические команды существующего конвейера **для старой ep03**, пока не подключён v2-адаптер:

```bash
python video/render.py ep03 still 36 77 108 156
python video/render.py ep03 sheet
# НЕ запускать 'all' над старой ep03 в качестве новой версии;
# старые сцены и published media этим пакетом не заменены.
```

Для v2 завести отдельную команду/папку и проверить, что файлы рендерятся отдельно. Не полагаться на случайно оставшиеся `timeline.json` и `audio/voice.wav` из предыдущего клипа.

### Фаза F — сборка и доказательства

Создать `render/final/ep03-v2-review.mp4`, SRT, contact sheet, JSON с решениями, документацию `render/final/ep03-v2-review-report.md`:

- commit SHA, renderer/tool versions, packages, asset licenses, используемые API;
- продолжительность и методика тайминга, количество кадров, спецификация финального файла;
- кадры S00–S11 с точными таймкодами на рабочей версии;
- таблица `Sxx → claimed law → primary source → human/independent reviewer → status`;
- тесты приёмки по `ACCEPTANCE.md`, найденные проблемы, исправленные версии и открытые вопросы;
- текст для альтернативного описания видео и контроль прослушивания без изображения.

**Не публиковать** в `content/media/ep03.mp4`, пока нет независимой правовой и визуальной приёмки, сравнения старой и новой версии и отдельного действия на публикацию.

## 3. Зависимости и API

Grokbot может использовать инструменты поиска, браузер, видеоанализ, кодовые агенты, композиционные движки, TTS, и API генерации изображений/видео для **вспомогательных** элементов. Выбирайте по измеряемым качеству/стоимости/воспроизводимости; для учебной геометрии prefer deterministic SVG/Canvas/GL/Blender.

Правило доверия:
- нормативные утверждения — официальный Matsne и отдельно проверенная модель;
- реальные ДТП — NTSB с ID, датой и фактом;
- геометрия / дорожные знаки — собственный программный генератор + визуальная проверка;
- LLM / GenVideo / GenImage — помощник, но не юридический валидатор и не источник фактов;
- внешний asset — проверенная лицензия/атрибуция; отсутствие лицензии означает не использовать;
- подключённые платные API — расходы только при явно согласованном бюджете, ключи только через secrets/env.

Не требуется покупать облачные мощности и специализированные продукты без демонстрации, что текущая среда не выдерживает минимальный прототип.

## 4. Оптимизация реальной стоимости и времени

- Сначала 2 × 15–25 сек preview c одним контрфактом; затем только части, которые прошли юридическую приёмку.
- Видео фрагментировать по Sxx: изменение S03 не должно требовать повторного рендера S10.
- Asset hashes + cache TTS по `voice + model version + parameters`.
- Preview 12fps/720p, финал после acceptance 24fps/1080p. Для векторного рендерера уменьшать supersampling только на прототипах.
- Постоянная камера в парных сценах позволяет переиспользовать слой окружения и автомобили, меняя только дорожную поверхность или знаки.
- Для поиска юридических источников хранить ссылки и версии, а не огромные повторные контексты.
- Каждый новый инструмент должен давать конкретный выигрыш, измеряемый на прототипе; не превращать проект в «конвейер из 15 агентов» без ответственного за результат.

## 5. Приоритет качества

**1) Право → 2) читаемость причины → 3) непрерывность и кинематографичность → 4) звук → 5) декоративные детали.** Если красота требует неверной конфигурации — убрать красоту, не исправлять закон.

Стоп-условия до публикации: любой неподтверждённый юридический выигрыш, подмена выезда перекрёстком, неверный знак, ложный «первый» при снеге, пропущенная оговорка NTSB, нечитабельный текст на телефоне, расхождение VO и кадра, невоспроизводимый рендер, чужой asset без разрешения, запись поверх старого `ep03.mp4`.
